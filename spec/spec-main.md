[ ] # OpenManus — 主规范文档

---

[ ] ## 1. 文档概述

[ ] ### 1.1 目的
[ ] 本文档作为 OpenManus 通用 AI Agent 框架的**主规范路由**，定义了项目的架构、模块划分、功能点和规范文件组织方式。所有修改、调整、查询、更新操作必须严格服从本路由规划。

[ ] ### 1.2 选择框机制（强制执行）

[ ] 所有规范文件中的主标题、二级标题、三级标题及其子条目前必须预留选择框标记 `[ ]`，用户确认后标记为 `[✓]`。

[ ] **选择框格式规范：**
[ ] - `[ ]` — 待确认/待实现（空框）
[ ] - `[x]` — 已拒绝/已废弃（小写x）
[ ] - `[✓]` — 已确认/已实现（对勾）
[ ] - 禁止使用大写X（如 `[X]`），必须使用小写x
[ ] - 选择框与后续内容之间建议有一个空格分隔

[ ] **层级继承规则：**
[ ] - 当父级标题被标记为 `[✓]` 时，其下所有子标题和子条目自动继承为 `[✓]`
[ ] - 子条目可独立标记，但父级标记为 `[✓]` 时子条目不能单独改为 `[ ]`
[ ] - 父级标记为 `[ ]` 时，子条目可独立标记为 `[✓]`（表示部分确认）

[ ] **强制执行规则：**
[ ] - 一旦条目被标记为 `[✓]`，不得删除或修改该条目的核心定义
[ ] - 后续 spec 规划和代码实现必须基于已打对号的条目进行
[ ] - 新增功能必须作为新条目添加，不得通过修改现有已确认条目实现

[ ] ### 1.3 规范文件结构

[ ] ```
spec/
├── spec-main.md                      # 主规范路由（本文件）
├── modules/                          # 模块规范目录
│   ├── spec-config.md                # 配置系统模块
│   ├── spec-agent.md                 # Agent 系统模块
│   ├── spec-tool.md                  # 工具系统模块
│   ├── spec-sandbox.md               # Docker 沙箱模块
│   ├── spec-daytona.md               # Daytona 云沙箱模块
│   ├── spec-llm.md                   # LLM 客户端模块
│   ├── spec-web-ui.md                # Web 界面模块
│   ├── spec-mcp.md                   # MCP 协议模块
│   ├── spec-flow.md                  # 多 Agent 流程模块
│   └── spec-prompt.md               # 系统提示词模块
└── features/                         # 功能点规范目录
    └── spec-daytona-sandbox.md       # Daytona 沙箱功能
```

[ ] ### 1.4 规范路由规则

[ ] | 选择 | 序号 | 操作类型 | 路由路径 | 说明 |
[ ] |:---:|:---:|---|----------|------|
[ ] | [ ] | 1 | 查询模块 | `spec/modules/spec-{模块名}.md` | 查看模块规范 |
[ ] | [ ] | 2 | 查询功能 | `spec/features/spec-{功能名}.md` | 查看功能点规范 |
[ ] | [ ] | 3 | 修改模块 | 修改对应模块文件 | 更新模块规范 |
[ ] | [ ] | 4 | 修改功能 | 修改对应功能文件 | 更新功能点规范 |
[ ] | [ ] | 5 | 新增模块 | 创建 `spec/modules/spec-{模块名}.md` | 遵循模块规范模板 |
[ ] | [ ] | 6 | 新增功能 | 创建 `spec/features/spec-{功能名}.md` | 遵循功能点规范模板 |
[ ] | [ ] | 7 | 删除模块 | 删除对应模块文件 | 同步更新主文档路由表 |
[ ] | [ ] | 8 | 删除功能 | 删除对应功能文件 | 同步更新主文档路由表 |

[ ] ### 1.5 规范一致性规则

[ ] | 选择 | 规则类型 | 说明 |
[ ] |:---:|--------|------|
[ ] | [ ] | 路由一致性 | 所有模块/功能必须在主文档中有记录 |
[ ] | [ ] | 命名一致性 | 文件名遵循 `spec-{模块名}.md` / `spec-{功能名}.md` |
[ ] | [ ] | 结构一致性 | 所有模块文件遵循统一模板 |
[ ] | [ ] | 版本一致性 | 相关联的规范文件版本保持同步 |
